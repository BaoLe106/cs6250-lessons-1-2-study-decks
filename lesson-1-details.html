Service ≠ protocol implementation

A layer's service is the promise exposed upward; a protocol is one way peers implement that promise. Preserve the service and lower technology can change.

Layering is not absolute

Functions can overlap or cross layers for performance and policy. The model remains useful because it identifies the responsibility being discussed.

Debug by boundary

Ask: signal? local frame? IP reachability? transport connection? application semantics? This narrows faults systematically.

Encapsulation detail

Headers identify the scope of a decision.

Transport header

ports identify the application endpoint; TCP adds sequence/ACK/window control.

IP header

source/destination IP allow routers to forward across networks.

Link header

source/destination MAC support delivery over the current local hop.

Physical encoding

makes a frame transmissible over the actual medium.

Peer principle: a layer's header is interpreted by the corresponding layer at its relevant peer. Link peers are adjacent; transport peers are end hosts.

End-to-end detail

“At the endpoints” does not mean “the network never helps.”

Correctness

An app can verify its file, encryption, or session state end-to-end even if a lower layer offers help.

Performance help

Networks may cache, filter, prioritize, or signal congestion—but that can add policy and deployment constraints.

Middlebox trade-off

NAT/firewalls solve scarcity/security, yet create state and can obstruct new end-to-end protocols.

Use the principle as a design lens: ask whether an in-network function can be complete without endpoint knowledge, then weigh the operational benefit of an exception.

Substrate

A lower-layer protocol a product relies on.

Product

A higher-layer protocol/application relying on substrates.

Competition

Similar protocols compete for adoption at a layer.

Design implication

Build coexistence/transition support before expecting a new core to deploy.

Learning bridge detail

Three forwarding cases determine most switch behavior.

learn first

Any received frame

Update source MAC → incoming port. This is why replies are valuable learning events.

known unicast

Destination is mapped

Forward only the mapped output (or filter if it is the same incoming port).

unknown/broadcast

Destination absent

Flood all outputs except incoming. This reaches the target but can be costly at scale.

Resource limit: selective forwarding does not create bandwidth. A busy output queues frames and eventually drops when buffers fill.

Spanning tree detail

A tree has connectivity without cycles.

Physical graph

May contain redundant edges for failure tolerance.

Active forwarding tree

For V bridge nodes, uses V−1 active inter-bridge edges; every node remains reachable.

Recompute

A failure changes the graph; blocked ports can become useful, so distributed messages converge again.

Separation to remember: learning chooses where a frame should go; STP chooses which topology paths are allowed to forward at all.
