Lesson 1 · design principles

General core, smart edges—and practical exceptions.

End-to-end

Only endpoints fully know application correctness, security, ordering, and session goals.

Why flexible?

Video can prefer low delay; file transfer can prefer every byte. The core avoids enforcing one trade-off.

NAT

Maps private IP:port to public IP:port; conserves IPv4 addresses and tracks reverse mappings.

Middleboxes

Firewalls/proxies/NAT add policy but can obstruct direct reachability or protocol evolution.

Answer framework: state the original principle, the application-level reason for it, then the operational reason an exception exists.

Lesson 1 · switching and STP

Know the two independent problems in a bridged LAN.

Learning bridge: where should a frame go?

On every arrival, learn source MAC → incoming port. Known destination → one port. Unknown destination → flood except incoming.

Spanning tree: which links may forward?

Physical redundancy creates cycles. Frames have no hop limit, so STP blocks selected ports to retain connectivity without active cycles.

Diagnostic distinction: MAC-table learning improves efficiency; STP prevents broadcast storms and unstable source-MAC learning.

Lesson 2 · transport addressing

IP selects the host; ports select the application; TCP's tuple selects the conversation.

UDP demux

Socket identity is destination IP + destination port. Many sources can deliver to that same destination socket.

TCP demux

Connection identity is source IP/port + destination IP/port. A server on port 80 distinguishes clients by their source tuple.

Multiplexing: sender gathers data from many sockets and labels segments. Demultiplexing: receiver reads those labels and delivers to the matching socket.

Lesson 2 · two limits

Every TCP throughput explanation starts with the smaller window.

LastByteSent − LastByteAcked
≤ min(cwnd, rwnd)
rwnd — receiver safety

Advertised free receive-buffer space. Low when the app reads slowly; zero-window probes discover newly freed space.

cwnd — network safety

Sender's safe in-flight estimate. Low when congestion is inferred from loss/delay/feedback.

Never merge the concepts: flow control prevents receiver-buffer overflow; congestion control prevents shared-path queues, loss, and collapse.

Lesson 2 · congestion-control playbook

Probe for capacity, then react to evidence.

Slow start

Cold start: cwnd grows roughly 1 → 2 → 4 → 8 per RTT until ssthresh.

AIMD/Reno

Near capacity: additive +1 packet/RTT; triple dup ACK halves cwnd; timeout is more severe and resets much lower.

CUBIC

High BDP paths: time-based cubic growth, cautious near last-loss Wmax, faster away from it.

Goals: high utilization, low delay, fair sharing, and fast convergence. Ideal AIMD fairness breaks with unequal RTTs or an app opening many parallel flows.
