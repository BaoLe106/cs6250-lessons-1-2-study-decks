Lesson 2 · detailed companion

Transport mechanisms, connected.

Socket namespace

Ports distinguish processes on one host. TCP's four-tuple distinguishes separate client-server conversations sharing the same server port.

Byte stream

TCP numbers bytes, not abstract messages. The receiving application sees ordered bytes after TCP handles reassembly.

Endpoint state

TCP has per-connection buffers, sequence state, timers, windows, and congestion estimates; UDP largely leaves such policy to apps.

Reliability detail

Reliable delivery needs both evidence and memory.

What arrived out of order?

Cumulative ACK idea: acknowledging the next expected sequence tells the sender all preceding bytes are in order. Duplicate ACKs expose a likely hole in that sequence.

Loss detection detail

Timeout and duplicate ACKs are complementary.

Timeout

Works even if no later packets arrive, but waits for an RTT-based timer.

3 duplicate ACKs

Acts sooner when later data did arrive, strongly suggesting one missing segment.

Why not use an extremely short timer?

RTT varies. A too-short timer mistakes delay for loss, retransmits unnecessarily, and can worsen congestion.

Reliability and congestion interact: TCP may see loss as both missing data to repair and a sign to reduce sending rate.

Flow-control detail

Two independent windows answer two different questions.

rwnd: “Can the receiver absorb more?”

Receiver computes free buffer capacity and advertises it. It depends on application read speed as well as arrivals.

cwnd: “Can the path absorb more?”

Sender estimates safe in-flight data from ACK/loss/congestion signals. It depends on shared bottleneck conditions.

in-flight bytes = LastByteSent − LastByteAcked
allowed in-flight bytes ≤ min(rwnd, cwnd)
Diagnostic clue: low throughput can be receiver-limited (rwnd) even when no path congestion exists, or path-limited (cwnd) with a ready receiver.

AIMD detail

Why the asymmetric shape?

Increasing cautiously tests for spare capacity without suddenly creating a large queue. Decreasing sharply responds to evidence that aggregate traffic exceeded a bottleneck.

Probe-and-adapt: TCP never learns a fixed “link speed.” It continually revises a safe sending estimate as competing flows and paths change.
Triple duplicate ACK

Reno treats this as a milder loss and roughly halves cwnd.

Timeout

Reno treats no ACK as more severe and returns to a much smaller window/slow start.

Slow start, avoidance, CUBIC

Different growth laws match different uncertainty.

Slow start

From little knowledge: start small, then approximately double per RTT until ssthresh.

Congestion avoidance

Near usable capacity: additive increase about one packet per RTT, multiplicative decrease at loss.

CUBIC

For high BDP paths: time-based cubic curve; fast far below Wmax, slow near prior loss point, then faster if it passes safely.

Fairness caveat: ACK-clocked Reno favors shorter RTTs and fairness is per flow, so many parallel flows can skew an application's share.

Datacenter detail

Where the network is controlled end-to-end, transport can evolve faster.

Workload

Many short flows are delay-sensitive; long queues are especially costly.

Control

One operator can coordinate endpoint and switch changes, unlike the public Internet's multi-operator ecosystem.

Examples

DCTCP uses ECN with loss behavior; TIMELY reacts to RTT-gradient delay signals.
